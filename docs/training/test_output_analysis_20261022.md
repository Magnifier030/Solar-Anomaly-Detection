# DNA-Net Test 輸出分析

本分析針對已提交的 `outputs/submissions/dnanet-ir-only-photo-20261022/submission.json`，SHA-256 為 `2d579ffbbc5fc760dd2a0433c0e3a598094349a927ea5e7b3085338239787cfa`。平台分數由使用者提供：hotspot TIoU=0.00437、F1_TIoU=0.00145、總分=0.0010203。沒有 Test GT，也沒有 Public/Private 清單，因此以下全 696 張 Test 的統計不能直接換算成平台分子的來源。原始提交檔未修改，也未建立新的提交版本。

## 可確認的輸出現象

| IR Test 來源外觀 | 影像數 | 有提交 polygon 的影像 | polygon 數 |
|---|---:|---:|---:|
| 灰階外觀 | 496 | 19（3.8%） | 27 |
| 偽彩外觀 | 200 | 55（27.5%） | 114 |
| 全部 | 696 | 74（10.6%） | 141 |

外觀分類使用來源 RGB 的平均 |R-G| + |G-B| < 1 作灰階啟發式；它不是官方 group，也不是正常／異常分類。Train 全部 1046 張在同一規則下都是灰階外觀。偽彩轉灰階是顏色亮度轉換，不會恢復溫度；但 Test 灰階子集同樣反應很少，因此不能把全部失敗歸因於偽彩。

提交 polygon 面積 min／P25／P50／P75／max 為 0.5／13／51.5／321／1897 像素²；27 個小於 10、86 個小於 100（61.0%）、131 個小於 1000（92.9%）。141 個輪廓分布於 74 張圖，平均每張有輪廓影像約 1.91 個；622 張沒有有效 polygon。這只是模型的作答覆蓋率，不是真正漏檢率，因為 Test 陽性影像數未知。

抽查 `gray_predictions.jpg` 與 `color_predictions.jpg`：不少預測位於板子下緣、角落或局部紋理，呈碎片狀，未沿整個模組邊界；`gray_no_predictions.jpg` 中也有肉眼可見局部亮點的影像沒有預測，但亮點不等於官方異常 GT。灰階 27 個輪廓中，22 個重心落在可見內容 bounding box 的底部 20%；17 個落在左側 20%，13 個同時符合。這支持檢查位置／邊界捷徑，但不是「已證明模型記住固定座標」。全部 38,744 個 mask 前景像素中僅 142 個落在近黑區（RGB max≤5），不是大量預測到全黑背景的問題。

## 門檻不是主要解法

使用同一最佳權重、相同 validation 前處理、eval 模式重算：

| threshold | 有至少一個前景像素的 Test 影像 | 前景像素總數 |
|---|---:|---:|
| 0.5 | 76 | 38,747 |
| 0.1 | 76 | 41,412 |
| 0.05 | 77 | 42,270 |
| 0.01 | 80 | 44,347 |
| 0.001 | 81 | 47,346 |

615／696（88.4%）影像的最大前景機率都小於 0.001；逐圖最大機率中位數約 4.50×10⁻⁹。模型對大部分影像強烈偏向背景，降低常用門檻並不能產生大量新的候選。上表是「任何像素」計數，原始提交的 74 張是「正面積 polygon」計數；少量孤立點或零面積線不會成為有效 polygon。

重算與原始保存的 696 張 mask 相比，只有 10 張共 11 個像素不同（總數 228,065,280），明確記錄此數值差異，不宣稱 bitwise 相同。已核對 checkpoint SHA-256、共用前處理、最後 supervision head、原尺寸與座標；未發現大規模輸出／座標錯誤，不能解釋平台落差為單純 JSON 包裝問題。

## 微調前後反應

在相同 Test、同一 threshold 0.5 下，PV-HSD 預訓練直接推論有 291 張出現前景像素、86,858 個前景像素；微調後降到 76 張、38,747 個。灰階子集由 163 張降至 19 張，偽彩子集由 128 張降至 57 張。

這是反應／覆蓋的下降，與微調對來源訓練場景的適應有關的假設一致，但不是預訓練比較準確的證據。預訓練以局部熱點框監督，與競賽整片模組標註不同；這裡不據此宣稱 catastrophic forgetting 已被因果驗證，也沒有提交預訓練版本去反覆試排行榜。

## 重要修正：小瑕疵不是一律學不會

同一照片切分最佳權重，重新將 validation 按 group 拆開：

| group | validation 影像 | pixel IoU | hotspot TIoU |
|---|---:|---:|---:|
| G01 | 57（僅 1 張正樣本） | 0 | 0 |
| G02 | 39（38 張正樣本） | 0.9366 | 0.7924 |
| G03 | 4（3 張正樣本） | 0.8827 | 0.1217 |
| G04 | 61（43 張正樣本） | 0.9593 | 0.8113 |

G02 的 GT polygon 面積中位數 948.5 像素²，G04 為 31,423.5。小物件的 G02 同場景驗證確實學得好，因此不能再說成「訓練瑕疵太大，所以所有小瑕疵都不會」。更符合證據的是同場景重複樣本讓驗證偏樂觀，而 Test 的外觀、熱點形態與位置變化沒有泛化。G03 的高 pixel IoU、低 polygon TIoU 也提醒整體 mask 重疊不等於每片模組都被正確分開。各 group 的樣本量差異很大，不應當作相同可信度的估計。

## 建議的後續實驗

1. 以 group-disjoint / leave-one-group-out 作主要選模，照片切分保留為擬合能力檢查；不依排行榜 Test 分數挑門檻。
2. 在有標註的訓練／驗證資料上，測位置、旋轉、亮度／對比變化，分別觀察全模組與局部熱點是否被混淆；這比只增加 epochs 更能檢查捷徑。
3. 比較較低 LR、凍結部分 encoder 或較短微調，觀察來源熱點能力是否保留；只能用固定驗證實驗判斷，不能因預訓練 Test 作答比較多就直接認定更好。
4. 若持續只圈到局部亮點，應評估「熱點候選 → 所屬模組輪廓」的結構；不要把局部熱點 mask 當作整個異常模組。
