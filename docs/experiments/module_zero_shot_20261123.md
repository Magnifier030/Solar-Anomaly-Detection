最重要的五個結論：

1. **先把任務定義做對，比換模型重要。** 補上 `solar_panel` 並改成逐模組多邊形後，panel 從 0 變成約 0.92。
2. **Text 的瓶頸是裂縫理由的用詞。** 只換一句理由，text 從 0.597 升到 0.849，總分增加約 0.076。
3. **Crack 的主要困難是有效正樣本極少。** 352 個標註裡，G01 的 34 個和 G07 的 8 個各自只是同一片實體模組。
4. **Hotspot 的主因是分數尺度無法跨場域。** v3 組內 AUC 有 .933–.995，但沿用其他組的門檻時，G04 召回只有 0.01–0.03。
5. **目前最佳成績含有測試集回饋，不能當成乾淨的泛化估計。** 見第 7 節。

## 1. 任務與評分

- 分數 = 0.7·F1_TIoU（panel、hotspot、crack 平均）+ 0.3·F1_TEXT。
- TEXT 使用 BERTScore（bert-base-chinese、第 8 層、rescale），依成因類別算平均後取調和平均，再做 `(raw−.3)/.4`。**任一類沒有配對成功，TEXT 就是 0。**
- 邊際規則：F1 ≈ 2T/(P+G)，新增預測只要精確度高於 F1/2 就會提升 F1。
- 標註是模組大小的多邊形，不是局部亮點。一個預測蓋住 n 片模組時，分數會大幅下降。
- 訓練 IR 全為灰階；測試 IR 有 200/696 張 inferno 偽彩。
- 測試影像多來自未見過的場域，因此只有留一組（LOGO）驗證有參考價值。

## 3. Solar panel 與 Text

- **Panel：** 以 Mask R-CNN 產生逐模組實例。先前訓練驗證會把相鄰模組合併，讓 panel TIoU 看起來是 0.684，對逐模組 GT 其實只有 0.397。
- **Text：** 訓練理由可分成 6 類且彼此不重疊。熱點依形狀分流到旁路二極體理由；裂縫改用「模組面板局部破裂，損傷位於表面。」。

## 4. Crack

### 有效的做法

| 階段 | crack TIoU | 關鍵改變 |
|---|---:|---|
| CLIP 閘門 | .058 | 文字提示零樣本 |
| 大模型 top-100 | .213 | DINOv2-L 高解析小缺陷描述子 + geo3/bi 擴增 |
| DINOv3-L | .327 | 只留 100 個，移除舊的低精確度裂縫 |
| CL 白斑 | .392 | SupCon 線性頭 + 2359 個合成白斑負樣本 |
| CL v3 | **.507** | 樹影反事實負樣本、修掉三角缺口被誤刪的 bug |

### 診斷

- 標註本身乾淨，未發現明顯錯標，也未在 G02/G03/G12 找到漏標。問題是**正樣本多樣性不足**。
- G07 唯一的裂縫模組位於樹影下，模型因此把陰影學成裂縫線索。加入反事實負樣本後，LOGO AUC 從 .889/.939/.997 變成 .961/.985/.996。
- 測試 GT 估計 160–360 個，只交 100 個會限制召回，但第 101 名之後的精確度明顯下降。

## 5. Hotspot

### v3 分數與 CL

- v3 = z(互評) + |z(std)| + z(局部亮點)，再排除邊界與截斷模組。
- CL：DINOv3-L 描述子 + 合成正樣本與反事實負樣本。LOGO AUC 為 .982/.975/.990/.981，v3 為 .933/.990/.995/.981。
- CL 適合用來刪掉無亮點的模組，對應平台 hotspot .317→.335，但提升幅度有限。

### 錯誤拆解（G01–G04）

- 上傳規則的精確度 .57、召回 .84。280 個誤報中有 240 個是「有熱點的畫面多選了其他模組」，集中在 G02。
- 但 G02 的 190 個標註是同一片模組，這個統計不能直接外推到測試集。

### 根因實驗（未使用平台分數）

不設每畫面上限，門檻只由其他三組決定：

| 分數 | 四組平均 F1 |
|---|---:|
| v3 | 0.269 |
| 互評 + 局部亮點 | 0.589 |
| **互評 + 畫面模板殘差** | **0.673** |
| 互評 + 模板殘差 + 場域 MAD（使用真實分組） | 0.724 |
| POT 極值門檻 | 0.12–0.29 |

- **多熱點互相掩護只是次要問題。** 移植 1→16 個熱點時，互評 AUC 從 .966 降到 .887，區間平均只回升到 .912，放進完整 v3 後幾乎沒差（.850 vs .854）。
- **主因是分數尺度。** 排序大致正確，但同一門檻無法跨場域使用。每畫面 top-K 其實是在掩蓋這個問題。
- **這些數字仍偏樂觀：** 16 種組合都在同樣四組上比較；實體熱點模組只有約 6–8 片；門檻穩定範圍僅 3.0–3.5；移植殘差本身由模板計算，對模板法有利；移植底圖 G05–G12 可能含未標註熱點。
- 在測試集上（t=3.5、無上限）會選出 998 個，其中偽彩 749 個。高分多有可見亮點，3.5–4.2 分段混有無亮點模組。**這個版本沒有建立提交檔，也沒有上傳。**

## 7. 省思

1. **不要擬合測試集。** 下列設定來自平台回饋，已帶有測試資訊：密集畫面 K4/thr3.5、裂縫排除清單（386+35）、裂縫 N=100、partition probe。之後的方法比較應以 LOGO 為主，平台只做最後確認。
2. **差異不顯著時，應回頭找原因。** 連續調 K、門檻和 swap 參數只帶來很小的變化，也無法說明問題。拆解錯誤後才發現主因是尺度。
3. **「每畫面上限」是症狀處理。** 它讓相對分數看起來可用，卻假設測試集的熱點密度和訓練集相同，而平台結果已顯示不成立。
4. **樣本數要算實體模組。** 444 個熱點其實約 6–8 片模組，AUC 再高，統計上也很脆弱。
5. **「沒有標註」不等於「正常」。** G05–G12 的處理錯誤曾直接造成 hotspot 崩落。
6. **肉眼判斷不可靠。** 看起來破裂的白斑不是 GT 裂縫，抽樣圖只能提出假設。
7. **先提出可被推翻的假設。** 多熱點掩護原本是主要假設，移植實驗證明它只是次要因素。
8. **驗證要對應失敗模式。** 舊驗證沒有無熱點的密集畫面，也沒有偽彩畫面，因此無法預警測試集上的問題。
9. **記錄每次上傳的 md5。** 曾有上傳錯檔造成分數完全相同的情況。

## 8. 下一步

依優先順序：

1. **盲場域分群：** 用畫面特徵分群，不使用真實分組，以 LOGO 檢查 0.724 能保留多少。
2. **門檻穩定性：** 讓分數跨場域有一致尺度，解決 3.0–3.5 過窄的問題。
3. **偽彩還原保真度：** 偽彩轉灰階可能失真（[調色盤偏差](https://arxiv.org/abs/2512.06504)），目前選出的熱點 75% 在偽彩畫面，訓練集卻沒有偽彩。
4. **跨電廠對比學習與噪聲容忍：** [PV IR SupCon/UDA](https://arxiv.org/pdf/2112.02922)、[SoftPatch](https://arxiv.org/pdf/2403.14233)。
5. **Crack 清理：** 移除來自平台回饋的排除清單，N 改由驗證集決定。

上傳條件：必須有已診斷的原因和對應方法，不為門檻或數量的小變化上傳。
